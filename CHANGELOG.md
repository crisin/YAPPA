# Changelog

One line per finished task (definition of done). Newest first.

## Unreleased

- Client core (C1): the app can now log in with an invite link (`yappa://invite/<code>?server=…`), keeps the login in the Windows credential manager / macOS keychain, sits in the presence room and sees who is online and in which channel, joins channels with tokens from the control plane, and remembers channels and config for when the server is away. Settings split into audio (engine) and app settings; old settings files are converted. `YAPPA_PROFILE=<name>` runs a second client on the same PC. The UI is wired to it in U5.
- Control plane (S6): `yappa-control` hands out invite links, channels and LiveKit tokens, keeps the minimum version and a kill switch, and writes an event log from LiveKit's webhooks; the first start prints an admin invite. Runs next to LiveKit in `home.yml` (Caddy publishes it under `/api/`), locally with `cargo xtask control`. The spike confirmed presence over a LiveKit room: a channel switch shows in about a millisecond on one machine, a kick in 10 ms, a crashed client after 20–23 s. Result in docs/spikes/s6-control.md.
- New window layout (U1): module rail on the left (Voice, Ich), the channel with its people in the sidebar, the voice box with mute, deafen and leave always at the bottom left, a search bar with `Strg K` that jumps anywhere, one banner line for problems (reconnecting, server unreachable, version too old), details for a person on the right, `Esc` steps back. Settings, diagnosis (the former debug panel) and help moved into „Ich“; the theme is remembered.
- UI foundation (U0): the second door `api.ts` with a mock control plane and presence room ("Die Gang" fixture, admin actions), mock scenes for browser mode and tests (`cargo xtask dev --ui --scene call|lobby|member|reconnect|offline|update`), the shell state with module registry, banner slot and palette commands, design tokens v1 (widths, type scale, state colours, focus, motion), Bits UI + Lucide installed, accessibility checked with axe in the UI tests. `api-types`: `Me`, `PublicConfig`, `Member`, `InviteCode`, `EventEntry`, `PresenceState` with the presence-room attribute mapping; `Presence` removed before it was ever used.
- Vision and architecture v1 (`docs/01-vision-v1.md`): full review after the UI concept — presence and live data move to a LiveKit presence room (ADR-005), settings split into engine and app schemas with a new `crates/client` for the non-audio client logic (ADR-007), settings become the module „Ich“ instead of an overlay and the UI gets Bits UI + Lucide (ADR-004), updates and remote config come from our own box and the repo goes to GitHub private (ADR-006). Realtime review of the engine (sound base; small prep E0 before the DSP chain), latency budget revisited, mobile sketched only. `TASKS.md` reorganised into the four phase-1 milestones M1–M4.
- UI concept v0 (lofi: shell with module rail, context sidebar, stage, voice dock, topbar + command palette, banner slot, inspector; call screen, onboarding, settings Einfach/Profi, admin; mobile parked) in `docs/ui/`, plus the implementation plan `docs/ui/02-umsetzungsplan.md` — work packages U0–U7 on the board. Mobile apps moved from non-goal to "later" in the planning doc. The in-app help now also renders `docs/ui/`.
- In-app help: the "Hilfe" button shows the repo's docs inside the app — tester guide, "So funktioniert yAPPA", glossary (new `docs/hilfe/`), and the project side (status = TASKS.md, changelog, ADRs, spikes, dev setup, home server). Rendered at build time by `cargo xtask docs` into a generated, committed JSON; search, links between pages, web links in the system browser. Glossary entries double as ⓘ tooltips in the debug panel and on labels.
- Dependencies: `rustls` 0.23.46 / `rustls-webpki` 0.103.16 and `webrtc-sys-build` 0.3.20 (pulls `zip` 9 instead of 0.6) — clears the RUSTSEC advisories that had turned `cargo deny` red in the gate.
- Test client: the app joins a room with a pasted invite and carries real voice — new crates `transport` (trait + LiveKit) and `audio-engine` (devices, mixer with per-person volume, levels, automatic rejoin), debug panel with live network and device statistics, structured log files with one-click diagnostics export, `cargo xtask livekit token` prints invites, headless engine example. ADR-003, docs/mittesten.md.

- Dev setup: `cargo xtask setup|doctor`, pinned toolchain, nextest/cargo-deny/insta/proptest/criterion, vitest + prettier, git hooks, Claude Code hooks/skills/agent — see docs/dev-setup.md.
